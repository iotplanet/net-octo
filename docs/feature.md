# NetOcto 网络调试工具需求文档

## 1. 项目概要

- **项目名称：** NetOcto
- **项目性质：** 跨平台桌面端网络调试工具
- **核心目标：** 集成通用网络协议（TCP/UDP）与行业特定协议（如 JT808/JT809）的调试能力，提供现代化的一站式调试体验。
- **技术栈：**
  - **桌面框架：** Tauri（Rust 核心 + Web 前端），当前支持 macOS
  - **协议解析：** 基于 xtream-codec（Java）构建独立协议解析服务
  - **用户界面：** React + HeroUI 风格现代化设计
- **许可证：** 本项目及 xtream-codec 组件使用木兰宽松许可证第 2 版（MulanPSL-2.0）。

## 2. 功能需求

### 2.1 核心通信功能

**TCP 通信**

- 实现 TCP Server 模式，支持多客户端连接管理。
- 实现 TCP Client 模式，支持连接、断线重连与心跳维护。

**UDP 通信**

- 实现 UDP Server 与 Client 模式。

**通用报文处理**

- 支持十六进制、ASCII、UTF-8 等多种格式的报文编辑与发送。
- 支持报文模板、变量替换（如时间戳、计数器）和循环发送。

### 2.2 协议解析功能

**集成 xtream-codec 服务**

- 作为核心协议解析引擎，处理 JT808、JT809 等协议的编解码。
- 提供协议字段的自动化解析与可视化展示。

**协议支持**

- 完整支持 JT808 协议（如位置汇报、终端注册等消息）。
- 完整支持 JT809 协议（如主从链路管理、平台间信息交互）。

**扩展性**

- 预留协议插件机制，便于未来集成其他定制协议。

### 2.3 数据与会话管理

- **会话记录：** 完整记录通信数据流，支持回放与导出。
- **报文模板库：** 支持模板的创建、管理、分类和快速调用。
- **历史数据：** 支持查询、过滤和对比历史通信数据。

### 2.4 用户界面与交互

**现代化界面**

- 采用类似 HeroUI 的现代化、清晰的设计语言。
- 支持暗色/亮色主题。
- 布局直观，包含连接面板、报文编辑区、解析展示区和监控仪表盘。

**核心交互**

- 连接配置与管理界面。
- 报文编辑与发送界面。
- 协议数据的树状或结构化展示。
- 实时流量、连接状态监控仪表盘。

## 3. 非功能需求

- **性能：** 界面响应流畅；协议解析服务调用延迟低；支持数百个并发网络连接的管理。
- **兼容性：** 桌面端支持 macOS（后续可扩展至 Windows、Linux）；协议解析服务需兼容 Java 运行环境。
- **可维护性：** 架构清晰，前端、Rust 核心、协议服务间耦合度低；代码结构良好，便于后续功能扩展与维护。
- **用户体验：** 安装与配置简单；操作符合直觉；提供必要的错误信息与日志，便于调试。

## 4. 系统架构

### 4.1 逻辑架构

```text
        ┌─────────────────────────────────┐
        │         NetOcto 桌面应用         │
        ├─────────────────────────────────┤
        │  React 前端 (HeroUI) │ Rust 核心 │
        │  • 用户交互          │ • 网络 I/O │
        │  • 状态管理          │ • 进程管理 │
        │  • 界面渲染          │ • 服务调用 │
        └──────────┬──────────▲──────────┘
                   │          │
         (前端请求) │          │ (解析结果)
                   │          │
         ┌─────────▼──────────┴──────────┐
         │    xtream-codec 协议服务       │
         │   (独立 Java 进程，HTTP 服务)  │
         │  • JT808/809 等协议编解码      │
         │  • 注解驱动，实体映射           │
         └────────────────────────────────┘
```

### 4.2 组件职责

**1. Tauri 应用（Rust + Web 前端）**

- **Rust 侧：** 负责桌面端原生能力，包括 TCP/UDP 网络通信、管理协议解析服务进程、通过 HTTP 客户端调用解析服务。
- **Web 前端侧：** 提供全部用户界面，处理用户交互，并通过 Tauri 提供的接口与 Rust 侧通信。

**2. 协议解析服务（Java）**

- 独立的、基于 xtream-codec 库构建的 Java 应用程序。
- 提供 HTTP API：接收二进制报文并返回结构化解析结果；接收构建参数并返回二进制报文。
- 专精于协议编解码逻辑，与 UI 和网络通信解耦。

### 4.3 关键交互流程

1. **用户发送数据：** 前端输入 → Rust 网络模块发送 → 目标设备。
2. **接收并解析数据：** Rust 网络模块接收 → 转发至 Java 协议服务 → 解析为结构化数据 → 返回 Rust → 推送至前端展示。
3. **构建协议报文：** 前端选择模板/填入参数 → Rust 调用 Java 协议服务构建接口 → 获取二进制报文 → 通过网络发送。

## 5. 未来扩展方向

- **协议扩展：** 通过插件机制集成 Modbus、GB/T 32960 等新协议。
- **平台扩展：** 将 Tauri 应用扩展至 Windows 和 Linux。
- **功能增强：** 自动化测试脚本、性能压测、流量分析与模拟等。
- **协同工作：** 支持会话文件共享，便于团队协作调试。
