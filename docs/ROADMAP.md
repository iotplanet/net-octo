# NetOcto 路线图

本文档区分 **已在仓库实现的能力**（与 [README.md](./README.md) 一致）与 **尚未实现、待规划交付的事项**（与 [docs/feature.md](./docs/feature.md) 对齐）。产品完整意图以 `docs/feature.md` 为准；**「已完成」以 README 描述为权威**，代码为准。

---

## 已完成（README 口径）

当前版本已具备的能力概览（细节见 README）：

- **桌面与栈：** Tauri 2 + React 19 + TypeScript；Vite SPA；网络在 **Rust（Tokio）**；UI 使用 **HeroUI v3**、**Tailwind CSS v4**。
- **会话模式：** TCP Server / TCP Client / UDP Server / UDP Client（UDP Client 支持单播 / 广播 / 多播配置）。
- **多 Tab：** 每 Tab 独立 `session_id`、后端 `NcState`、`localStorage` 持久化（`netocto.settings.v1.<tabId>`）。
- **载荷与收发：** ASCII / HEX 发送与接收切换；HEX 支持 `//` 整行注释与格式化显示；发送侧可选 ASCII 转义解析；**循环发送**。
- **报文编辑：** 多行编辑器、选区发送、发送历史面板、注释与载荷的语法风格高亮。
- **运行时信息：** 通过 Tauri 事件推送日志、客户端列表、统计、服务端状态（如 `nc-log`、`nc-clients`、`nc-stats` 等）。
- **国际化：** 中英 UI 文案、浏览器语言与设置内切换。
- **工程与命令：** `nc_start_session`、`nc_stop_session`、`nc_stop_server`、`nc_send`、`nc_disconnect`、`nc_reset_stats` 等（见 README 表格）。

**明确未实现（README 已声明）：** 行业 / 私有协议（如 JT/T 808、1078、809、905 等）**尚未接入**；当前为通用字节流会话实验栈。

### 阶段 B — Java 协议服务与 JT808 / JT809

- 独立 **xtream-codec（Java）** 进程，**HTTP API**：二进制 → 结构化解析；参数 → 二进制构建。
- Rust 侧：**进程生命周期**（启动 / 托管 / 健康检查 / 异常对用户可见）。
- 前端：协议字段**树状或表格**展示；与收发流水线对接（发送前构建、接收后解析）。
- JT808、JT809 消息覆盖度按 `docs/feature.md` 持续扩充。

### 阶段 C — 数据、模板与监控深化

- 与阶段 A 待办重叠项的**落地规格**（导出格式、存储与性能、回放语义）。
- 模板库与变量 / 循环发送的**一体化**产品化。
- 历史与对比功能的**数据模型与 UI** 定型。

### 阶段 D — 平台与生态扩展

- **平台：** Windows、Linux 打包与 CI（Tauri 目标矩阵内验证）。
- **协议：** 插件机制；Modbus、GB/T 32960 等（顺序按业务优先级）。
- **能力：** 自动化测试脚本、性能压测、流量分析与模拟（可拆分子里程碑）。
- **协作：** 会话 / 配置文件共享与团队调试工作流。
